# cad-surface-mesher 结构求解器用于 V18 抽屉的可行性实测

日期：2026-11-25
对象：`mizy/cad-surface-mesher` @ `afae3bd`（feat: extend structural solver and browser workflows）
本机：Mac 8 GB，Rust 1.99，Python 3.12.13（仓库内 `.venv`）

## 结论

**能跑通，但对整个抽屉算出来的数不能信。**

- 求解链路本身是完整的：STL → T10 体网格 → 线性静力 → 形变云图 / HTML 报告 / VTP / 反力与能量闸门，全流程在本机 2 分钟内跑完（18,648 单元 / 36,209 节点 / 108,627 DOF）。
- 问题在**体网格**：`stl_volume.mesh_stl()` 对真实薄壁件生成的网格严重畸变，单元边长中位数 0.22 mm、最大 266 mm，有 745 个单元的形心落在抽屉空腔（空气）里。以此算出的 2 kg 载荷位移 0.29 µm、峰值应力 23.45 MPa 都是畸变单元的伪结果，不能作为设计依据。

## 实测记录

### 算例

- 输入：`../fea_drawer_infill/drawer_printed.stl`（闭合、水密，实体体积 163,876 mm³）
- 材料：PETG 等效 E = 1400 MPa、ν = 0.35（按 10% gyroid 夹芯折算 0.70；原代码只内置钢/铝/钛/铸铁，材料由驱动脚本注入，未改仓库）
- 约束：`x_min, x_max, y_min, y_max`（四周外壁面全固定）
- 载荷：`z_min: fz=-19.6`（2 kg 均布在底面）
- 网格：3.0 mm；后端 auto（GPU 失败后自动回退 CPU f64）

同一份 `volume.msh` 的统计：

| 指标 | 数值 |
|---|---|
| 单元体积分位数 p50 / p90 / p99 / max | 0.0004 / 0.139 / 13.3 / 13,974.8 mm³ |
| 边 0-1 中位 / 最大 | 0.22 mm / 266.2 mm |

网格尺寸被设成 3 mm，实际出现 266 mm 的跨腔单元，说明 `MeshSizeMin/Max` 只作用于内部补充点，源 STL 的原始面片没有被细分，gmsh 直接拿粗面片连出了大单元。

## 代码级限制（读源码确认）

1. **自动网格尺寸 = bbox 最小边 / 2**（`serve_web.py: prepare_case`）。抽屉最小边 86 mm → 43 mm 单元，等于没法用；必须绕开 prepare_case 自己指定尺寸。
2. **只接受单个闭合 STL（≤10 MB）**，不修补、不装配、不做多体。V18 是 19 件套，要一件一件算。
3. **实体 T10 线性小应变**，没有壳单元、没有中面提取、没有接触/蠕变/层间各向异性。0.96 mm 侧壁在实体网格里只能有一层单元，弯曲刚度会被高估。
4. **材料硬编码** 4 种金属，PETG 需要外部注入（本目录驱动脚本做了）。
5. **`单元 Jacobian > 0` 闸门是写死的 `passed: True`**（`solve.py`），报告显示全绿也不代表网格可用。这一点在本次实测里直接踩中。
6. `solve.py --mesh` 路径有 bug：`read_msh22()` 返回 tuple 却被当 `TetMesh` 用，必崩。已在本地克隆补了 3 行包装（未提交）。
7. 原生求解器在 121,718 节点算例上抛 `buffer is not large enough ... f64`，回退 Python scipy spsolve；365k DOF 的算例单核跑 7 分钟以上，8 GB 机器有 OOM 风险。

## 适用 / 不适用

**适合**

- 参数化 box / hinge 的自校验（内置解析梁/拉杆基准）
- 厚实实体件：夹持块、凸轮、定位榫、握把，这类几何比薄壁件更容易得到可接受网格
- 已经有可信体网格（外部 gmsh 生成 `.msh`）时的方程求解与报告输出

**不适合**

- 整个薄壁抽屉或任何 1 mm 级壁厚的整件受力
- 需要壳/中面模型、接触、螺钉预紧、层间强度、蠕变寿命的问题
- 装配体（多件互相受力）

## 和已有薄板模型的对照

`../fea_drawer_infill/REPORT.md` 的 Kirchhoff + Morley 薄板模型给出 2 kg 均布：四边简支 0.75 mm、四边固支 0.21 mm。本次实体算例本应落在 0.2–0.8 mm 区间，实际给出 0.0003 mm，差三个数量级，属于网格失效而不是物理结论。

## 本目录产物

- `run_solid_case.py`：绕开自动网格，指定尺寸后调用 `solve.run_solve`；支持注入任意材料；`--geometry box:...` 走参数化路径
- `run_chain.sh`：等依赖/二进制约就绪后顺序跑算例
- `fea_solid_drawer_2kg/`：整抽屉算例（含 `*_report.html`、`*_deformed.vtp`、`volume.msh`、`summary.json`）

## 如果要继续推进

优先级从高到低：

1. 用 FreeCAD 把 `04_Drawer.step` 转成带尺寸场的 gmsh 网格（壁厚方向至少 2 层单元），再喂 `solve.py --mesh`；先只算底板 + 两侧壁的局部段，不要整件。
2. 给仓库补 PETG 材料、修 `--mesh` bug、把 Jacobian 闸门换成真实检查（体网格最小 Jacobian / 长宽比），否则报告不可审计。
3. 整件仍以薄板/梁模型加实物验证为准；实体求解只做局部交叉验证。
